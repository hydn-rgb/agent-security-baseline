## 结论先行

**上一轮的 PASS 是隔离沙箱的合成数据压测，不是真实环境实测。本次补做真实环境实测，结论不同：**

- 六个模块在真实会话数据上全部跑通（exit=0，总耗时 3.639 秒）。
- **L5 组合告警：真实 0 告警**（1138 次调用、0 次敏感路径读、23 次外联事件）——过去没有"读凭据→外联"行为，与早前 1004 次调用的人工审计结论一致。
- **L3 凭据卫生：REVIEW，3 个高风险可达**——这是真实缺口，合成压测因故意设空凭据路径而未暴露。
- **L4 出站：16 个白名单外 host**——均为镜像/包源/内网地址的只读请求，无数据外传特征，但白名单基线未收敛。

### L3 真实缺口明细

| 路径 | 风险 | 内容（仅元数据） |
|---|---|---|
| `~/.ssh` | HIGH | 私钥 `id_ed25519`、`id_rsa` 存在 |
| `~/.workbuddy/keyblob` | HIGH | 密钥库存在 |
| `~/.workbuddy/security` | HIGH | 安全目录存在 |

自动化权限模式仍为 `fullAccess`——这些凭据与 agent 同用户、同权限可达。**这是"能力面"缺口：过去没被读不等于读不到。** 修复动作见 `L3_L5_操作清单.md`，需你本人授权执行，本项目不自动迁移。

### L4 出站白名单外 host（16 个，代表性）

模型镜像站(6)、官方服务域名(3)、内网地址(1)、包管理器官方源、依赖统计站、安全公告站、文档站、高校镜像源 等。**域名已脱敏**（原文见本地 `data/egress_audit.json`，不入库、不上传）。

判定：全部为出网只读请求（模型镜像 + 包源 + 技术资料站 + 内网服务），**无数据外传特征**。但 `config.example.json` 的 `allowed_egress_hosts` 未覆盖这些，属白名单基线未收敛——建议按你的真实出网需求更新 `config.json`（不上传）。

> 脱敏说明：本报告为公开仓库文档，所有真实 host / 内网 IP / 本机路径均已替换为类别描述或占位符；原始值仅存于本地 `data/*.json`（已被 `.gitignore` 排除）。

## 三、合成压测 vs 真实实测对照

| 维度 | 合成压测（上一轮） | 真实实测（本轮） |

| 结论 | 逻辑正确性 PASS | 存在真实能力面缺口 |

**关键教训**：合成压测验证的是"逻辑对不对"，真实实测验证的是"环境安不安全"。前者 PASS 不能替代后者——L3 缺口只有在真实数据上才现形。

## 四、发现的项目改进点（未擅自修改，供决策）

1. **`summary.verdict` 不聚合子模块 REVIEW/ALERT**：六模块全 exit=0 就判 PASS，会掩盖 L3 的 REVIEW。建议改为"任一模块 verdict ∈ {REVIEW, ALERT} 则总 verdict 同步降级"。
2. **remote_scan 覆盖有限**：本次扫描范围内仓库 0，需传入你真实的团队仓库根才有意义：`python modules/remote_scan.py <你的仓库根>`。
3. **白名单基线**：按真实出网需求收敛 `config.json` 的 `allowed_egress_hosts`。
